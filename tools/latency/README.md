# latency

WAV ファイルから、打鍵音（キークリック等の物理的な操作音）とそれに続く発音（キック音等、
アプリが鳴らす音）の立ち上がりの時間差（レイテンシ）を計測する CLI ツールです。

想定する録音: **1秒に1回程度、ゆっくり打鍵したときの録音**。打鍵音の後、一定時間内の最初の
大きな立ち上がりを「発音」とみなします（打鍵音自体の減衰を発音と誤検出しません）。

## ビルド

```sh
cd tools/latency
cargo build --release
```

実行ファイルは `target/release/latency` に生成されます。

## 使い方

```sh
cargo run --release -- <WAVファイルのパス> [オプション]
# または
./target/release/latency <WAVファイルのパス> [オプション]
```

例:

```sh
./target/release/latency recordings/session1.wav
```

出力例:

```
組  1: click=  200.023ms  kick=  300.522ms  遅延= 100.499ms
組  2: click=  700.023ms  kick=  800.522ms  遅延= 100.499ms
...
検出10組: 中央値=100.499ms  最大値=100.499ms
```

検出できたペアが1組も無い場合（無音の録音を渡した場合など）は、次のように「0組」であることを
明示して正常終了します（「0ms」と誤って表示することはありません）。

```
検出0組: 打鍵音（クリック）→発音（キック等）のペアを検出できませんでした。
  （無音、しきい値が合っていない、または発音が一度も鳴っていない可能性があります。
   --click-threshold / --kick-threshold を調整して再実行してください。）
```

## 対応する WAV フォーマット

8/16/24/32bit の整数 PCM、および 32bit 浮動小数点 PCM に対応しています（`hound` クレートでデコード）。
ステレオなど複数チャンネルの場合は、各サンプル位置でチャンネル間の振幅絶対値の最大値を使って
モノラル相当のエンベロープとして扱います。

## オプション（しきい値のチューニング）

| オプション | デフォルト | 説明 |
|---|---|---|
| `--click-threshold` | `0.02` | 打鍵音（クリック）の立ち上がりとみなす振幅のしきい値（0.0〜1.0、フルスケール比）。環境ノイズより大きく、打鍵音の音量より小さい値にします。 |
| `--kick-threshold` | `0.2` | 発音（キック等）の立ち上がりとみなす振幅のしきい値（0.0〜1.0、フルスケール比）。`click-threshold` より大きい値にします。打鍵音の音量より大きく、発音の音量より小さい値にします。 |
| `--max-window-ms` | `300` | 打鍵音の後、発音を探す最大時間（ミリ秒）。この時間内に発音が見つからない場合は「未ペア（発音なし）」として扱います。 |
| `--quiet-ms` | `30` | 発音（または未ペアの打鍵音）を検出した後、次の打鍵音の検出を再開するために必要な「静けさ」の継続時間（ミリ秒）。発音の減衰・余韻を次の打鍵音と誤検出しないための設定です。 |
| `--release-ms` | `8` | エンベロープフォロワーの release 時間（ミリ秒）。通常は変更不要です。 |

### しきい値の調整方法

録音環境やマイクの感度によって、打鍵音・発音それぞれの振幅は変わります。デフォルト値で
「検出0組」になってしまう場合や、逆に無関係なノイズを打鍵音として拾ってしまう場合は、
音声編集ソフト（Audacity 等）で WAV の波形を確認し、打鍵音のピーク振幅・発音のピーク振幅の
だいたいの値を見た上で、`--click-threshold` をノイズフロアと打鍵音の間、`--kick-threshold` を
打鍵音と発音の間の値に調整してください。

## 検出アルゴリズムの概要

1. 振幅（絶対値）の低いしきい値（`click_threshold`）を最初に超えたところを「打鍵音」の立ち上がりとみなします。
2. その直後から `max_window_ms` 以内に、より高いしきい値（`kick_threshold`）を最初に超えたところを「発音」の立ち上がりとみなします。
   - 打鍵音自体の音量が `kick_threshold` を超えないようにしきい値を調整する前提です。
   - 遅延が0msに近く打鍵音と発音がほぼ同時に鳴っている場合、合成波形の振幅が `click_threshold` を超えた瞬間にはすでに `kick_threshold` も超えているため、同じサンプル位置が両方の立ち上がりとなり、正しく「差0ms」と判定されます。
3. 発音（または未ペアの打鍵音）を検出したら、振幅が `click_threshold` を `quiet_ms` の間ずっと連続して下回るまで、次の打鍵音の検出を休止します。減衰していく音は波形が0点を何度も横切るため、瞬時振幅が一瞬しきい値を下回っただけでは「鳴り止んだ」と判定せず、一定時間連続して静かな状態が続いたことをもって次の検出を再開します（そうしないと、まだ鳴っている発音の減衰の途中を新しい打鍵音として誤検出してしまいます）。
4. `max_window_ms` 以内に発音が見つからなかった場合は「打鍵音は検出したが発音が見つからなかった（未ペア）」として記録し、集計対象からは除外した上で次の打鍵音の検出へ進みます。

## テスト

```sh
cargo test
```

以下を自動テストで検証しています（`src/lib.rs` の単体テスト、`tests/integration.rs` の結合テスト）。

- 「クリック音の 0ms / 30ms / 100ms 後にキック音」を10組並べた WAV（プログラムで生成、ファイルはコミットしない）に対して、各ケースで期待値 ±2ms の精度で遅延を検出できること。
- 無音だけの WAV を与えると「検出0組」となり、`0ms` と誤って出力しないこと。
- 打鍵音は鳴ったが発音が一度も鳴らなかった場合、「未ペア」として記録され、遅延0msのペアとして誤集計されないこと。
- 実際に hound で WAV ファイルへ書き出し → 読み込みを行う end-to-end 経路でも、上記の検出精度が保たれること。

## スマホの録音（m4a）を WAV に変換する

このツールは WAV のみ読み込めます。iPhone 等で録音した `.m4a` は、Mac 標準の `afconvert` で
変換してください（詳細は [`../README.md`](../README.md) も参照）。

```sh
afconvert -f WAVE -d LEI16@44100 input.m4a output.wav
```
