# latency

WAV ファイルから、打鍵音（キークリック等の物理的な操作音）とそれに続く発音（キック音等、
アプリが鳴らす音）の立ち上がりの時間差（レイテンシ）を計測する CLI ツールです。

想定する録音: **1秒に1回程度、ゆっくり打鍵したときの録音**。打鍵音の後、一定時間内の最初の
大きな立ち上がりを「発音」とみなします（打鍵音自体の減衰を発音と誤検出しません）。

## ビルド

```sh
cd tools/latency
cargo build --release
```

実行ファイルは `target/release/latency` に生成されます。

## 使い方

```sh
cargo run --release -- <WAVファイルのパス> [オプション]
# または
./target/release/latency <WAVファイルのパス> [オプション]
```

例:

```sh
./target/release/latency recordings/session1.wav
```

出力例:

```
組  1: click=  200.023ms  kick=  300.522ms  遅延= 100.499ms
組  2: click=  700.023ms  kick=  800.522ms  遅延= 100.499ms
...
検出10組: 中央値=100.499ms  最大値=100.499ms
```

遅延が `--min-delay-ms`（既定3ms）未満で「判定不能」に分類されたペアがある場合は、次のように
明示した上で、中央値・最大値の集計からは除外します（「0ms」を正常な計測結果として紛れ込ませることはありません）。

```
判定不能: 2 組（遅延が --min-delay-ms（3ms）未満のため、物理的にありえない値として除外し、中央値・最大値の集計に含めていません）。
  判定不能  1: click=  200.023ms  kick=  200.045ms  遅延=   0.022ms
  判定不能  2: click=  700.023ms  kick=  700.041ms  遅延=   0.018ms
```

検出できたペアが1組も無い場合（無音の録音を渡した場合など）は、次のように「0組」であることを
明示して正常終了します（「0ms」と誤って表示することはありません）。

```
検出0組: 打鍵音（クリック）→発音（キック等）のペアを検出できませんでした。
  （無音、しきい値が合っていない、または発音が一度も鳴っていない可能性があります。
   --click-threshold / --kick-threshold を調整して再実行してください。）
```

## 対応する WAV フォーマット

8/16/24/32bit の整数 PCM、および 32bit 浮動小数点 PCM に対応しています（`hound` クレートでデコード）。
ステレオなど複数チャンネルの場合は、各サンプル位置でチャンネル間の単純平均を取ってモノラル化してから
解析します（周波数帯分離フィルタには符号付きの波形が必要なため、振幅絶対値ではなく単純平均を使います）。

## オプション（しきい値のチューニング）

| オプション | デフォルト | 説明 |
|---|---|---|
| `--click-threshold` | `0.02` | 打鍵音（クリック）帯域（ハイパス後）で、立ち上がりとみなす振幅のしきい値（0.0〜1.0、フルスケール比）。環境ノイズより大きい値にします。 |
| `--kick-threshold` | `0.1` | 発音（キック等）帯域（ローパス後）で、立ち上がりとみなす振幅のしきい値（0.0〜1.0、フルスケール比）。周波数帯で分離しているため、`click-threshold` との大小関係に制約はありません。 |
| `--click-highpass-hz` | `1000` | 打鍵音帯域を取り出すハイパスフィルタのカットオフ周波数（Hz）。この周波数以上に主なエネルギーがある音を打鍵音として扱います。通常は変更不要です。 |
| `--kick-lowpass-hz` | `200` | 発音帯域を取り出すローパスフィルタのカットオフ周波数（Hz）。この周波数以下に主なエネルギーがある音を発音として扱います。通常は変更不要です。 |
| `--min-delay-ms` | `3` | これ未満の遅延（ミリ秒）は物理的にありえない値とみなし、「判定不能」として扱います（中央値・最大値の集計から除外）。 |
| `--max-window-ms` | `300` | 打鍵音の後、発音を探す最大時間（ミリ秒）。この時間内に発音が見つからない場合は「未ペア（発音なし）」として扱います。 |
| `--quiet-ms` | `30` | 発音（または未ペアの打鍵音）を検出した後、次の立ち上がりの検出を再開するために必要な「静けさ」の継続時間（ミリ秒）。発音の減衰・余韻を次の立ち上がりと誤検出しないための設定です。 |
| `--release-ms` | `8` | エンベロープフォロワーの release 時間（ミリ秒）。通常は変更不要です。 |

### しきい値の調整方法

録音環境やマイクの感度によって、打鍵音・発音それぞれの振幅は変わります。デフォルト値で
「検出0組」になってしまう場合や、逆に無関係なノイズを打鍵音として拾ってしまう場合は、
音声編集ソフト（Audacity 等）で WAV の波形を確認し、打鍵音のピーク振幅・発音のピーク振幅の
だいたいの値を見た上で、`--click-threshold` / `--kick-threshold` をそれぞれのノイズフロアより
大きい値に調整してください（周波数帯で分離しているため、打鍵音の方が発音より大きく録れていても
問題ありません）。

## 検出アルゴリズムの概要（周波数帯分離方式）

打鍵音（キークリック等の物理的な操作音）は高域、発音（キック等、アプリが鳴らす音）は低域に
主なエネルギーがある、という前提で、振幅の大小ではなく**周波数帯**で両者を区別します。
これは、スマホをキーボードの近くに置いて録音すると打鍵音の方が発音より大きく録れることがあり、
振幅だけで判定すると打鍵音自身を発音と誤検出してしまう（実際の遅延を大きく過小評価する）
問題があったための設計です。

1. 波形を一次IIRフィルタ（RC回路相当）で2つの帯域に分離します。打鍵音は `click-highpass-hz`
   （既定1000Hz）以上を通すハイパスフィルタ、発音は `kick-lowpass-hz`（既定200Hz）以下を通す
   ローパスフィルタにかけます。
2. それぞれの帯域で独立にエンベロープ（振幅の絶対値にピークホールド式のリリースをかけたもの）
   を作り、独立にしきい値（`click-threshold` / `kick-threshold`）を超えた立ち上がり時刻を検出します。
   周波数帯で分離しているため、打鍵音の振幅が発音より大きくても、発音側の帯域には打鍵音の
   高域成分がほとんど残らず誤検出しません（逆方向も同様）。
3. 打鍵音の立ち上がりを古い順に見て、それぞれについて `max-window-ms` 以内にある最も早い
   （まだ使っていない）発音の立ち上がりとペアにします。見つからなければ「未ペア（発音なし）」
   として記録します。
4. ペアの遅延（発音時刻－打鍵音時刻）が `min-delay-ms`（既定3ms）未満の場合は、物理的に
   ありえない値として「判定不能」に分類し、出力に明示した上で中央値・最大値の集計から除外します。
   実際の機器・OS・アプリの処理を経て3ms未満で発音することは考えにくいため、その場合は
   検出側の誤り（帯域漏れ等）を疑うべき、という考え方です。
5. 検出した打鍵数より、ペア（有効＋判定不能）の総数の方が多くなっている場合は、検出ロジックに
   矛盾がある可能性があるとして警告を出します。

発音（または未ペアの打鍵音）を検出した後は、振幅が `quiet-ms` の間ずっと連続してしきい値を
下回るまで、次の立ち上がりの検出を休止します（減衰していく音の0点交差の連続検出を防ぐため）。

## テスト

```sh
cargo test
```

以下を自動テストで検証しています（`src/lib.rs` の単体テスト、`tests/integration.rs` の結合テスト）。

- 「クリック音の 30ms / 100ms 後にキック音」を10組並べた WAV（プログラムで生成、ファイルはコミットしない）に対して、各ケースで期待値 ±2ms の精度で遅延を検出できること。
- 遅延0msのケースは、物理的にありえない値として「判定不能」に分類され、`0ms` を正常な計測結果として誤って出力しないこと。
- 無音だけの WAV を与えると「検出0組」となり、`0ms` と誤って出力しないこと。
- 打鍵音は鳴ったが発音が一度も鳴らなかった場合、「未ペア」として記録され、遅延0msのペアとして誤集計されないこと。
- 打鍵音が発音より大きく（またはほぼ同等に）録れているケース（打鍵音0.5・発音0.3、打鍵音0.5・発音0.8、いずれも遅延100ms）で、打鍵音自身を発音と誤検出して「約0ms」と誤読しないこと（正しく100ms付近と読むか、判定不能と明示するかのいずれかになること）。
- 検出した打鍵数よりペア数の方が多い矛盾した状態を人為的に作った場合に、警告が出ること。
- 実際に hound で WAV ファイルへ書き出し → 読み込みを行う end-to-end 経路でも、上記の検出精度が保たれること。

## スマホの録音（m4a）を WAV に変換する

このツールは WAV のみ読み込めます。iPhone 等で録音した `.m4a` は、Mac 標準の `afconvert` で
変換してください（詳細は [`../README.md`](../README.md) も参照）。

```sh
afconvert -f WAVE -d LEI16@44100 input.m4a output.wav
```
